# Contrast audit

Generated by hand this session (`docs/CLAUDE-CODE-PROMPT.md` T5.6), from the exact hex values in `tokens/global.tokens.json` / `tokens/semantic.light.tokens.json` / `tokens/semantic.dark.tokens.json`, using the WCAG 2.x relative-luminance contrast formula. **Not yet wired into an automated `scripts/contrast-audit.mjs`** that regenerates this file and fails CI on a regression (T1.2's own note called this out as future work) — this is a one-time, manual verification run, dated below, not a standing gate. Re-run by hand (or, better, automate it) whenever a colour token changes.

Thresholds per BRAND.md / `docs/CLAUDE-CODE-PROMPT.md` ground rule 8: **AAA (7:1)** for body and muted text, **AA (4.5:1)** for other text, **AA (3:1)** for non-text UI (focus outlines, borders that carry meaning).

**One finding, pre-existing:** `text.muted` (`#5D554D`) on the page ground (`#FAF8F4`) is 6.89:1 against BRAND.md's own stated 7:1 AAA bar for muted text — short by 0.11, about a 1.6% gap. This is the *original* muted-text colour, unchanged by this session's token migration (T1.2 carried the exact pre-existing hex forward); it is not a regression this rebuild introduced, but it is a real, measurable miss against the standard this same rebuild asserts. **Not fixed this session** — darkening `#5D554D` by even one step (e.g. to `#564E46`, ~7.3:1) is a real, site-wide visual change to every `.meta`/`.lede`/muted-text instance across ~70 pages, and changing it without a visual pass is exactly the kind of blind edit this session has avoided throughout (see the T1.4/T1.6 "deferred, not silently fixed" pattern). Flagged here for a deliberate fix with visual verification, not left silently passing.
