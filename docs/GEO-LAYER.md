# The machine-readable layer

Everything on this site that is written for a crawler or an answer engine
rather than for a reader, and where each piece is generated.

The organising rule, which every item below follows: **a machine-readable claim
is a claim.** A `lastmod` that is really a build timestamp, a `sameAs` pointing
at an abandoned profile, a `HowTo` with invented steps, and a fabricated review
are the same offence at different volumes. When we cannot state something
truthfully, the property is absent — not defaulted, not guessed, not hedged.

## What is generated, and from what

| Artifact | Source of truth | Generated by |
| --- | --- | --- |
| `/llms.txt` | the `articles` content collection + a curated static list | `src/pages/llms.txt.ts` |
| `/robots.txt` | hand-maintained | `public/robots.txt` |
| `/sitemap-index.xml`, `/sitemap-0.xml` | routes Astro built | `@astrojs/sitemap` in `astro.config.mjs` |
| sitemap `lastmod` | article dates, else git | `src/lib/lastmod.ts` |
| Organization, WebSite | hard-coded site identity | `src/layouts/BaseLayout.astro` |
| BreadcrumbList | the crumbs the page renders | `src/components/Breadcrumbs.astro` |
| Article, HowTo, FAQPage, CollectionPage | article frontmatter | `src/layouts/ArticleLayout.astro` |
| Recipe | article frontmatter | `src/lib/schema.ts` |

## llms.txt

An H1, one paragraph of orientation, then `## ` sections of
`- [title](absolute url): summary` links.

Generated, not checked into `public/`, because a hand-maintained index of a
growing site is a stale index of a growing site. Two consequences worth knowing:

- **Article summaries are the article's own `description`.** Not a second
  sentence written for crawlers, which would be free to drift from what the
  page says.
- **Static pages are advertised only if `src/lib/nav.ts` would render them.**
  An entry marked `pending` there is filtered out. This is the guard that stops
  `llms.txt` linking `/camping` before `/camping` exists — the one way this file
  could actively mislead an engine that trusts it.

## robots.txt

`Allow: /` for `*`, plus each answer engine and AI crawler named explicitly and
allowed explicitly: GPTBot, OAI-SearchBot, ChatGPT-User, ClaudeBot, Claude-Web,
PerplexityBot, Google-Extended, Bingbot. The wildcard already permits them;
naming them removes the ambiguity and gives us one line to change per agent if
that ever needs to change.

`ChatGPT-User` is named beyond the list originally specified. It is the agent
that fetches a page *because a person asked a question that our page answers* —
the single most citation-relevant crawler on the list.

`/thanks` is disallowed, carries `noindex, follow`, and is excluded from the
sitemap. All three, because they do different jobs: robots.txt stops the fetch,
the meta tag removes a URL already indexed (a crawler that cannot fetch a page
cannot read a directive inside it), and the sitemap exclusion stops us
advertising a URL we have asked crawlers not to visit.

There is no `/tools/batch-log/export` route to disallow. The Batch Log's export
is a client-side download; nothing is served.

## Sitemap lastmod

Two questions, answered two ways — see the header comment in
`src/lib/lastmod.ts`.

- **Articles:** `updatedDate ?? publishedDate`, at midnight UTC. The same
  convention the visible byline and the `Article` JSON-LD use, so all three
  agree about when a page changed. This is what makes a comparison page's
  ninety-day re-check promise legible to a crawler.
- **Static pages:** the last commit that touched the page's source file, from a
  single `git log` pass per build.
- **Neither available:** no `lastmod`. A missing date costs a little crawl
  efficiency. A wrong one — today's date on every page, every build — teaches a
  crawler that our dates are noise, which destroys the value of the true ones.

The build prints one `[lastmod]` line saying how many entries were dated and
from where, and warns when the git index is empty. A shallow CI clone silently
producing no dates is exactly the failure that would otherwise ship unnoticed.

## Known gaps

- **No guide or comparison declares `howTo[]` or `faq[]`.** Only the four
  troubleshooting articles do. The HowTo and FAQPage builders are correct and
  tested; they have nothing to act on for eight of ten articles. This is a
  content gap, and closing it means writing real steps, not generating them.
- **No article declares an `image`.** Every `Article` ships without an `image`
  property and every hero renders nothing. Part B wires the slots.
- **Sitemap `loc` and page `<link rel=canonical>` disagree about the trailing
  slash.** The sitemap advertises `/about`; the page's canonical says
  `/about/`. `trailingSlash: 'never'` in the Astro config agrees with the
  sitemap, so the canonical is the odd one out. Not changed here: it needs a
  decision about redirects at the edge, not a find-and-replace.
- **`sameAs` is empty.** Correct today; fill it the day a maintained profile
  exists.

## Tests

- `tests/schema.test.mjs` — the builders in isolation, then the built HTML in
  `dist/`: per-template `@type` sets, no duplicate top-level types, the
  Organization's contact route, and the negative cases (no steps declared means
  no `HowTo`). Also asserts `robots.txt` and `llms.txt` as shipped.
- `tests/lastmod.test.mjs` — date resolution, including the shallow-clone shape
  where git is unavailable.

Both read `dist/`, so `npm run build` must run first. CI already does
(`.github/workflows/ci.yml` builds before it tests).
